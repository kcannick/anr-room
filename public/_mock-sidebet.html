What this mockup is deliberately NOT showing
Sponsor banner is the existing banner system. packs.banner_id → the banners table, uploaded in the console like a room banner, served by /api/banner/image, click-through via link_url. No new table, no second uploader, no new image storage. It does not fall back to the global house banner: the page says "courtesy of our sponsor," so showing an unrelated advertiser there would be a lie. No pack banner set = no slot rendered.

No pick counts anywhere. The tiebreak ranking is built from the entries themselves, so showing "340 people picked this" would make copying the crowd the best strategy — it raises your number right and wins the tiebreak. Everyone submits the same 18, everyone ties, and the winner is whoever entered first. Hidden until settle, enforced server-side. This rules out exactly the engagement widget that would feel most natural to add.

No admin surface yet. Needs a CSV pack loader (row order is load-bearing — it breaks ties in the consensus ranking), pack_song_a/b stamped on each Versus round so the played 18 derive for free, and a host confirm-and-settle checklist. The join that decides a cash prize can't be a title string compare.
